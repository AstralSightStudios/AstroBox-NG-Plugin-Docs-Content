穿戴设备是离用户最近的一块屏幕。它戴在手腕上，一天会被看上百次。我们希望 AstroBox 官方社区源里的每一个表盘、快应用、模块和资源包，都配得上这个位置。

注意：本文参考来自 Apple Developer 的 [App 审核指南](https://developer.apple.com/cn/app-store/review/guidelines/) 编写。在质疑本文之前，也许你正在质疑地球上最伟大的科技公司。

本文是 AstroBox 官方社区源的审核准则。提交至官方社区源的资源，必须满足本文的全部要求。存在问题时，审核员会在 Pull Request 中公开提出修改意见；完成修改并通过审核后，资源才会合并发布。资源名称、封面、图标、简介与预览图等展示信息的具体要求，请参阅 [资源基本信息规范](/docs/creator-tools/resource-std/info)。

## 简介

AstroBox 资源社区的指导原则非常简单 — 我们希望为用户打造更安全可靠的穿戴设备资源探索平台，并为所有创作者提供获取成功的绝佳机会。为此，官方社区源中的每个资源都会经过专人审核，编辑团队也会定期帮助广大用户发现新的资源。

在以下页面中，你会发现我们已把准则划分为五个部分：安全、性能、商务、设计及法律。每条准则都有编号，审核员提出修改意见时会引用对应编号（例如「不符合准则 2.6.2」），方便你快速定位问题。AstroBox 资源社区一直在不断变化和改善，紧跟用户与设备的需求。你的资源也需要做出改变与改进，才能留在官方社区源上。

在官方社区源发布资源，还需注意以下几点：

- 官方社区源向所有用户免费开放浏览，也向所有创作者开放投稿。上架免费资源不需要任何付费，质量是唯一的门槛；即使你给我们打钱，开通 CreatorPlus、CreatorPro 等创作者权益，也不会降低本准则中的任何质量与安全要求。
- AstroBox 的用户中也有未成年人。请记住，你的资源可能会出现在他们的手腕上。
- 官方社区源面向成千上万的陌生用户。如果你只是想把资源分享给亲朋好友，直接把包体发给他们安装会更合适。
- 你要确保资源中的所有内容都符合本准则，包括你引用的第三方素材、字体、SDK 与网络服务。
- 如果你试图欺骗审核（例如在审核期间隐藏功能、在审核通过后通过远程配置改变资源行为、抄袭他人作品、操纵评论或推荐），我们会下架你的资源，并可能封禁你的创作者账号。

## 我们的选品原则

AstroBox 的首页是一条以封面为主的资源信息流。我们不以资源数量衡量社区，而是希望用户在这条信息流里随手点开的任何一个资源，都值得装到自己的手腕上。为此，我们按以下原则挑选上架的资源：

- **少而精。** 信息流里的每一个位置都很珍贵。一个平庸的资源占据一个位置，就意味着一个优秀的资源少被看到一次。我们宁可少上架，也不让粗糙、重复的内容进入信息流。
- **美观是基本要求。** 用户先看到封面，再看到资源本身。封面、图标、预览图与资源界面的视觉质量都是审核的一部分，而不是加分项。
- **所见即所得。** 用户在信息流里看到什么，安装后就应该得到什么。
- **对用户负责。** 资源必须在声明支持的设备上稳定运行，不耗电、不发热、不损坏设备，也不损害用户的隐私和钱包。
- **对创作者公平。** 原创作品应当得到保护，抄袭与搬运不应获得流量。

如果你做出来的是一坨连你自己都不愿意安装的狗屎，在这种情况下进行提交，我认为是一种侮辱，你也是个傻逼。

## 提交之前

为了帮助你尽可能顺利地通过资源审核，请查看下方列出的常见问题，这些问题可能会导致审核流程延误或资源被拒。这些内容不能代替准则，也不能保证资源获批，但逐项核对这个列表会是一个良好的开始。

请确保：

- 在你声明支持的每一款设备上实际安装并测试资源，确认不会崩溃、不存在明显错误。
- 资源信息完整且正确，并符合 [资源基本信息规范](/docs/creator-tools/resource-std/info)。
- 你的邮箱能收到 GitHub Pull Request 的通知。我们认为面向成百上千个陌生人沟通时使用实时通信软件是一种陋习，可能也是缺乏社会经验的体现。审核沟通统一在 Pull Request 中公开进行，请留意审核员的回复。
- 向审核团队提供资源的完整访问权限。如果你的资源包含付费内容或基于账户的功能，审核员可能会进行询问。你应该根据审核员的要求提供有效的演示账户或全功能演示模式，以及审核资源时所需的任何其他条件（例如激活码乃至激活码生成算法、附带软件中账号系统的完整访问权限）。
- 如果资源依赖你自己的服务器，请确保服务在审核期间保持在线。
- 在 Pull Request 描述中说明不易发现的功能、付费内容的解锁方式、模块的系统拓展行为，以及更新版本相对上一版的变化。
- 提交模块时，在 Pull Request 中完整说明模块的能力与对系统的修改。模块会经过更严格的安全审计，见准则 2.6.4。
- 快应用使用正式发布包，而非 Debug 包，见准则 2.6.2。

### 自动检查项

CreatorConsole 会在发布时检查以下项目，审核员也会在审核时进行额外检查。未通过的项目会导致无法提交或被要求修改：

| 检查项 | 要求 |
| --- | --- |
| 资源 ID | 表盘：以 `9798` 开头的 12 位数字；快应用：快应用包名；模块：以小写字母开头，仅含小写字母、数字和下划线，最长 16 个字符；资源包：1–12 个字符，仅含小写字母、数字、`_` 和 `-` |
| 包体与资源 ID | 快应用包体内的包名必须与资源 ID 一致 |
| 包体类型 | 包体的实际类型必须与所选资源类型一致 |
| 版本号 | 每个包体都必须填写 `versionCode`；更新时必须大于已上架版本；表盘的 `version` 与 `versionCode` 必须一致 |
| 快应用签名 | 必须为正式发布包，不得使用开发工具内置的调试证书签名 |
| 图标 | 正方形（1:1），边长不超过 500px |
| 封面 | 严格为 3:2，文件大小不超过 600 KB |
| 图片格式 | 图标、封面与预览图均不支持 SVG，修改扩展名的 SVG 同样会被识别 |
| 简介与标签 | 简介必填；标签至少 3 个 |
| 作者 | 至少一位作者绑定 AstroBox 账号 |
| 外部链接 | 仅支持 HTTPS，不得指向内网或私有地址 |
| 加密上传 | 开启加密上传的设备，必须同时开启「启用购买与资源加密相关功能」 |

自动检查只能发现格式问题。通过了全部自动检查，并不代表资源一定能通过审核。

## 1. 安全

当用户从 AstroBox 安装资源时，他们希望获得安全的体验：资源不含令人不快的内容，不会损坏设备，不会窃取数据，也不会在使用中造成人身伤害。如果你想恐吓或伤害他人，你的资源不适合出现在 AstroBox 中。

### 1.1 令人反感的内容

资源（包括其名称、封面、图标、预览图与简介）不得包含具有攻击性、令人不安或低俗不堪的内容，包括但不限于：

- **1.1.1** 色情、低俗或带有性暗示的内容。
- **1.1.2** 诽谤、歧视或恶意的内容，包括针对宗教、民族、性别、性取向、地域、国籍或其他群体的攻击与羞辱。
- **1.1.3** 写实的暴力、血腥、虐待内容，或者鼓励暴力、自残的内容。
- **1.1.4** 宣扬赌博、毒品、烟草、电子烟或过量饮酒的内容，以及鼓励未成年人接触上述物品的内容。
- **1.1.5** 政治敏感、不良导向的内容，以及其他违反 [中华人民共和国法律](https://flk.npc.gov.cn/index) 或用户所在地法律法规的内容。
- **1.1.6** 利用灾难、冲突、疫情等公共事件进行炒作或牟利的内容。

### 1.2 虚假信息与伪造数据

如果你是一名AI Kidders，你最需要做的是管好你的Agent，不要让它在发动鬼脑意淫神秘功能的同时只是显示mock数据。

- **1.2.1** 资源中看起来像实时数据的元素（时间、日期、电量、步数、心率、血氧、天气等）必须绑定真实的数据源。纯装饰性的数字，不得以容易被误认为真实测量值的方式展示。
- **1.2.2** 不得提供伪造来电、伪造消息通知、伪造支付或收款成功界面、伪造身份凭证等用于恶作剧或欺诈的功能。即使注明「仅供娱乐」，也不能违背这一准则。
- **1.2.3** 不得仿冒系统界面（例如系统弹窗、系统更新提示、低电量警告）诱导用户操作。

### 1.3 健康与人身安全

- **1.3.1** 涉及健康数据的资源只能展示设备系统提供的测量结果，不得声称资源本身具备诊断、治疗或医疗级测量的能力。例如，声称仅凭一个表盘或快应用就能测量血压、血糖或体温的资源会被拒绝。
- **1.3.2** 提供健康建议的资源，应当提醒用户在做出医疗决定前咨询医生。
- **1.3.3** 不得鼓励用户以可能伤害自己或他人的方式使用设备，例如参与危险挑战或极端节食。

### 1.4 未成年人保护

- **1.4.1** 资源的名称、封面、图标与预览图会出现在所有用户的信息流中，因此必须适合全年龄用户，即使资源本身面向成年人也是如此。
- **1.4.2** 明显面向未成年人的资源，不得包含诱导消费、诱导添加陌生人联系方式，或跳转至不适合未成年人的内容的设计。

### 1.5 用户生成内容

包含聊天、评论、投稿等用户生成内容的资源，必须满足以下条件：

- 过滤违法和令人反感的内容，避免其被发布；
- 提供举报机制，并及时处理举报；
- 能够取消发布违规内容的用户的使用资格；
- 公开作者或运营方的联系方式。

以随机匿名聊天、色情内容或人身攻击为主要用途的资源，不适合出现在 AstroBox 中。

### 1.6 作者信息

用户需要知道资源来自谁，以及遇到问题时如何联系你。资源至少要有一位作者绑定 [AstroBox 账号](/docs/creator-tools/account/ab)，且作者名称必须与该账号的唯一名字 ID 一致。我们建议你在外部链接中提供可以联系到你的主页或反馈渠道。

### 1.7 恶意行为与数据安全

- **1.7.1** 资源不得包含病毒、木马、后门、远程控制代码，或其他会危害用户设备、数据与账号安全的内容。
- **1.7.2** 资源不得在用户不知情的情况下收集、上传或转卖用户数据，也不得试图获取用户的账号密码。
- **1.7.3** 资源收集的用户数据必须妥善保护，防止泄露和未经授权的访问，详见准则 5.1。
- **1.7.4** 不得伪装包体类型，例如把固件、可执行程序或其他文件伪装成表盘或快应用提交，除非你在资源简介中特别声明。

## 2. 性能

### 2.1 资源完整性

- **2.1.1** 提交审核的资源应当是最终版本。占位文字、空白页面、未完成的界面与测试用内容，应在提交前移除。
- **2.1.2** 资源不得包含明显影响使用的故障，包括无法安装、无法启动、核心功能失效、严重显示异常或频繁崩溃。
- **2.1.3** 资源必须具备基本完整度、原创性与实际使用价值。仅替换模板图片的表盘、功能过于简陋的快应用等低质量资源可能无法通过审核。
- **2.1.4** 资源中的付费内容、账号功能与联网服务在审核期间必须可用，且处于完整、最新的状态。审核员无法访问的功能，请在 Pull Request 中说明原因。

### 2.2 测试版资源

官方社区源只接收面向所有用户公开发布的正式版本。演示版、Beta 版与内测版不适合上架，请通过你自己的渠道分发给测试者。试用包的要求见准则 3.1.3。

提示：如果你有 CreatorPlus 或 CreatorPro 会员，你可以使用 CreatorConsole 提供的 “测试分发” 功能。

### 2.3 准确的元数据

- **2.3.1** 资源的名称、简介、封面与预览图必须与实际内容一致，不得夸大功能或误导用户。
- **2.3.2** 不得包含隐藏、休眠或未说明的功能。所有功能对用户和审核员都应清晰可见；新增功能、付费方式的变化与系统拓展行为，必须在 Pull Request 中说明。
- **2.3.3** 预览图可以经过设计包装，但展示的界面必须来自资源的真实运行效果，不得展示资源中并不存在的界面或功能。
- **2.3.4** 名称、标签和简介中不得堆砌无关关键词、其他资源或品牌的名称、价格信息，或者「最强」「官方」「第一」等无法证实的宣传语。标签参与搜索与推荐，请只填写与资源贴合的标签。
- **2.3.5** 请为资源选择正确的资源类型。所选类型与实际情况不符时，审核员会要求你修改。
- **2.3.6** 封面与预览图中出现的个人信息（姓名、手机号、头像等）应当是虚构的，不得展示真实他人的数据。
- **2.3.7** 资源的名称、图标应与资源安装后在设备上显示的名称、图标保持一致，以免引起用户困惑。

### 2.4 设备兼容性

- **2.4.1** 资源必须能在其声明支持的每一款设备上正常运行基本功能；未经验证的设备不得标记为支持。
- **2.4.2** 同一资源适配多款设备时，请在同一个资源下为每款设备分别添加下载，而不是为每款设备单独上架一个资源。
- **2.4.3** 资源不应快速耗尽电量、导致设备明显发热，或对设备造成不必要的负担。例如，不得无故高频刷新、长时间强制保持屏幕常亮、持续占用传感器或蓝牙，或在后台运行与资源功能无关的任务。
- **2.4.4** 资源不得建议或要求用户重启设备、恢复出厂设置，或修改与资源核心功能无关的系统设置。

### 2.5 版本与更新

- **2.5.1** 每次发布必须提供明确、可辨识的资源版本号，并在 `downloads` 中如实填写 `version` 与 `versionCode`。
- **2.5.2** 更新资源时必须递增版本号，不得以相同或更低的版本号覆盖已上架版本。
- **2.5.3** 同一版本号必须对应同一份资源内容；资源文件发生变化时，应同步更新版本号。
- **2.5.4** 同一构建适配多个设备时，应使用一致的版本号；不同设备版本存在功能或内容差异时，应分别准确标注。
- **2.5.5** 不得通过无实际内容的版本更新反复刷新资源。
- **2.5.6** 版本更新不得降低资源的基本可用性；存在已知限制时，应在资源简介或更新日志中明确告知。
- **2.5.7** 更新日志应清楚描述本次更新的内容。简单的错误修复可以概括说明，但移除功能、改变付费方式、新增系统拓展行为等重大变化必须单独列出。

### 2.6 打包要求

- **2.6.1** 官方社区源目前接收表盘、快应用、模块与资源包四类资源。包体的实际类型必须与所选资源类型一致。
- **2.6.2** 快应用不接收 Debug 包体。请使用正式发布命令（`aiot release`）并以你自己的证书签名打包，在上架前确认不是调试包。
- **2.6.3** 快应用包体内的包名必须与资源 ID 一致，包内显示的名称应与资源名称一致。
- **2.6.4** 模块自身权限极高。出于对用户设备安全的考量，模块资源类型会经过比其他资源更严格的安全审计。审核过程中，你有义务如实回答审核员关于模块行为与实现的问题，并配合完成审计。
- **2.6.5** 模块声明的兼容信息（ABI、目标设备、最低框架版本）必须与实际测试情况一致，不得为扩大覆盖面而虚报兼容性。
- **2.6.6** 资源包（`.crpack`）必须符合 CRPack 格式：压缩包根目录有且仅有一个 `corona.json`，不得包含 `mappings.tsv`、符号链接、加密条目或不安全的路径；解压后的总大小不超过 64 MiB，映射规则合计不超过 256 条。资源包 ID 即设备上的主题目录名，上架后不可更改。资源包目前仅支持小米原生设备，请勿为其他设备标记支持。
- **2.6.7** 资源需要依赖其他资源或插件才能正常使用时，必须在 `ext.bundledResources` 中以 `required` 或 `recommended` 声明捆绑安装，而不是要求用户自行搜索安装。

### 2.7 软件要求

- **2.7.1** 资源应在自身范围内运行。不得在审核通过后，借助远程配置、远程下发脚本等方式启用未经审核的功能，或改变资源的性质。
- **2.7.2** 资源不得屏蔽或破坏系统的基础能力，例如返回手势与按键、表盘切换、通知、设置、健康测量与设备重置。
- **2.7.3** 具备系统拓展能力的模块，必须在简介与 Pull Request 中明确说明修改了哪些系统行为；用户卸载或停用模块后，系统应恢复原状。
- **2.7.4** 资源包只应替换其声明的资源文件。替换系统图标或界面资源时，不得使电量、警告、设置项等系统关键信息变得无法辨认。

## 3. 商务

AstroBox 支持创作者通过付费资源获得回报。如果你的付费方式并不直观，请在简介和 Pull Request 中加以说明。如果审核员无法理解资源如何收费、如何解锁，审核会有所延误，资源也可能被拒绝。价格由你决定，但请让用户付出的每一分钱都物有所值。

### 3.1 付费类型

- **3.1.1** 每个资源都必须如实选择付费类型，各类型的适用情况见下表。
- **3.1.2** 试用版、包含应用内购买的资源必须标注为付费，不得隐瞒功能限制或收费内容。付费资源会在首页被明显标注，用户也可以一键过滤付费资源。
- **3.1.3** 如果你为资源提供了试用包，试用包应能体现资源的核心体验，并在开始试用前清楚告知试用的时长或功能限制，以及获取完整版的方式。
- **3.1.4** 不得以免费资源的名义上架，却在安装后要求付费才能使用核心功能。

| 付费类型 | 适用情况 |
| --- | --- |
| 免费 | 全部内容可直接使用，没有任何付费内容 |
| 付费 | 例如包含IAP（In-App Purchase）的快应用，或其关联的插件/手机App包含付费内容 |
| 强制付费 | 不购买则无法使用，即使提供试用版 |

### 3.2 定价与价值

- **3.2.1** 付费资源应提供与售价相符的完成度、稳定性和使用价值。
- **3.2.2** 定价明显高于其内容价值的资源，可能会被要求调整价格或被拒绝。
- **3.2.3** 资源内的抽奖、盲盒等随机获取机制，必须在用户付费前披露每种物品的获取概率。

### 3.3 购买与解锁

- **3.3.1** 资源内的购买引导必须指向真实可用、由你本人运营或授权的购买渠道。我们推荐使用 AstroBox 已经接入的 [爱发电](/docs/creator-tools/resource-management/paid-resources) 或 [自有网站授权](/docs/creator-tools/resource-management/external-authorization)，用户可以在 AstroBox 内完成购买与安装，无需手动输入激活码。
- **3.3.2** 不得要求用户评论、点赞、转发、关注账号、加入群聊或下载其他资源之后，才能使用资源的功能或获取激活码。
- **3.3.3** 用户付费后应能顺利解锁所购买的内容，重新安装资源后也应能恢复已购内容。如果授权与设备绑定、更换设备后需要重新购买，必须在用户购买前明确告知。
- **3.3.4** 发布付费资源需要 CreatorPlus 或更高档位的创作者权益。

### 3.4 免费与付费资源比例

未购买 CreatorPro 赞助权益的作者，在官方社区源上传的免费资源数量必须是付费资源的 2 倍以上，详见 [资源比例要求](/docs/creator-tools/resource-std/rate)。

### 3.5 售后与持续支持

- **3.5.1** 售出付费资源后，你有义务为购买者提供合理的售后支持，并在资源内或外部链接中提供可用的反馈渠道。
- **3.5.2** 付费资源长期无法正常使用、且作者不再维护时，我们可能会下架该资源。

### 3.6 诚信经营

- **3.6.1** 不得通过刷下载量、刷评论、小号互评、以付费或奖励换取好评等方式操纵评论、排名或推荐，也不得委托他人代为操作。
- **3.6.2** 不得使用多个账号规避本准则或资源比例要求。

## 4. 设计

我们认为，用户看重简单、精致、富有创意且易于使用的资源。以下准则只是最低要求，而不是我们对资源的全部期待。

### 4.1 原创与抄袭

- **4.1.1** 请拿出你自己的想法。不得简单照搬他人的热门资源，或者只是细微修改他人资源的名称、配色或界面，就作为自己的作品提交。存在争议时，审核员会在 Pull Request 中讨论并要求补充说明。
- **4.1.2** 禁止未经原作者授权搬运、转载或盗传他人资源。
- **4.1.3** 不得冒充其他创作者、AstroBox 官方或设备厂商发布资源，也不得在名称、图标中使用他们的品牌与标志，暗示与其存在合作或获得其认可。

### 4.2 最低功能要求

- **4.2.1** 快应用不应只包含一张图片、一段文字、一个二维码或一组链接。仅用于展示营销内容、广告或引流信息的资源会被拒绝。
- **4.2.2** 资源应能独立工作。需要依赖其他资源或插件时，请按准则 2.6.7 声明捆绑安装。
- **4.2.3** 模块应具有明确的、用户可以感知到的用途。

### 4.3 重复与刷屏

- **4.3.1** 同一资源只上架一次。同一资源的不同设备版本，请按准则 2.4.2 合并在一个资源下。
- **4.3.2** 仅在配色、背景图或个别元素上有所不同的一系列资源，应尽量合并为一个资源（例如在表盘内提供可切换的样式），不得拆分成大量独立资源占据信息流。
- **4.3.3** 简单数字时钟表盘、仅有一张背景图的表盘、计算器、手电筒、电子木鱼、随机抽签等类型的资源在 AstroBox 中已经相当丰富。除非提供有实质性差异或改进的体验，否则我们不会接受新的同类资源。
- **4.3.4** 请勿在短时间内大量提交质量相近的资源。比起数量，我们更希望看到你把精力放在少数几件出色的作品上。

### 4.4 穿戴设备体验

- **4.4.1** 资源界面应当为穿戴设备设计，并适配目标设备的屏幕形状与分辨率：内容不得被圆角或屏幕边缘裁切，文字应清晰可读，可点击区域应足够大。使用 AI 一键生成、完全不适合在穿戴设备上使用的资源可能无法通过审核。
- **4.4.2** 表盘应能让用户一眼读出当前时间。以时间为核心的创意设计（例如抽象的时间表达）不受此限，但仍需保证时间可以辨认。
- **4.4.3** 快应用应遵循穿戴设备的交互习惯，支持系统的返回手势或按键，操作路径应尽量简短。
- **4.4.4** 动画与转场应当流畅，不应出现明显的卡顿、闪烁或画面撕裂。
- **4.4.5** 资源中不得包含第三方广告。表盘与快应用的主界面不得放置二维码、群号、店铺名等引流信息；作者署名应保持克制，不得影响主要信息的阅读。
- **4.4.6** 如果表盘提供息屏显示，息屏界面应以深色为主、尽量减少亮起的像素，以控制功耗。

### 4.5 设计质量

视觉质量是审核的一部分。如果资源的界面、封面或图标设计过于粗糙、难以入眼，或者完全不适合在信息流中展示，即使功能完整，也可能无法通过审核。设计无法用具体的审核细则衡量，审核结果也会受到审核员审美判断的影响；如果你对「设计不通过」的结论有异议，可以申请扩大审核，见 [提交之后](#提交之后)。

如果你对封面设计缺乏经验，可以先阅读 [封面小指南](/blog/resource-cover-guide)，从模仿学习（不是像素级复刻）开始。

### 4.6 生成式 AI

- **4.6.1** 你可以使用 AI 辅助创作，但不得将 AI 一键生成、未经打磨的内容直接提交。AI 生成的素材同样需要满足本准则在质量、原创与版权方面的全部要求。
- **4.6.2** 我们不推荐直接使用 AI 生成封面，此类封面基本上很难通过审核。

## 5. 法律

资源必须遵守 [中华人民共和国法律](https://flk.npc.gov.cn/index) 以及用户所在地的法律法规。下面列出的只是一些常见问题，遵守法律始终是你自己的责任。

### 5.1 隐私

- **5.1.1** 收集任何用户数据之前，必须征得用户同意，并告知收集了哪些数据、用于什么目的、是否会分享给第三方。收集个人信息的资源，应在外部链接中提供隐私政策。
- **5.1.2** 只收集与资源核心功能直接相关的数据。付费功能不得以用户授予无关的数据权限为前提。
- **5.1.3** 如果资源的核心功能不依赖账号，请允许用户在不登录的情况下使用。支持注册账号的资源，应当提供注销账号的方式。
- **5.1.4** 健康、位置等敏感数据不得用于广告或营销，也不得在未经用户明确同意的情况下分享给第三方。
- **5.1.5** 未经他人同意，不得使用、传输或分享其个人信息，也不得暗中追踪用户或汇编用户资料。

### 5.2 知识产权

- **5.2.1** 资源中使用的图片、插画、字体、音频、代码等素材，必须由你本人创作或获得合法授权。不得直接取用他人的插画、摄影作品，商用字体需持有相应授权，或改用允许商用的开源字体。
- **5.2.2** 基于知名 IP 进行创作时，必须在预览图（`preview`）中加入版权声明图，明确该素材及 IP 与 AstroBox、小米及其他设备厂商无关。权利人提出异议时，我们会下架相关资源。
- **5.2.3** 审核员或权利人提出疑问时，你需要提供素材授权或原创证明。我们收到有效的侵权投诉后，会下架相关资源。
- **5.2.4** 不得误导或暗示 AstroBox、小米或其他设备厂商是资源的来源或提供方，或以任何形式认可资源的质量与功能。
- **5.2.5** 使用天气、地图、音乐等第三方服务时，请确保你遵守其使用条款并获得了必要的许可。不得提供从第三方平台违规下载受版权保护内容的功能。

### 5.3 违法用途

- **5.3.1** 不得提供用于考试作弊、偷录、窃听、跟踪定位他人等违法或侵犯他人权益用途的功能。
- **5.3.2** 不得提供真实货币的赌博、彩票或博彩辅助功能。
- **5.3.3** 资源内的抽奖、比赛等活动必须由你本人主办并公布活动规则，同时明确说明 AstroBox 不是活动的主办方或赞助方。

### 5.4 创作者行为准则

请尊重每一个人，无论是在回复用户评论、处理售后，还是与审核员沟通时。

- **5.4.1** 不得骚扰、歧视、恐吓或攻击用户、其他创作者与审核员，也不得鼓励他人这样做。回复用户评论时，请直接回应评论内容，不要在回复中夹带广告或他人的个人信息。
- **5.4.2** 你提供的作者信息必须真实、最新，不得冒充他人。
- **5.4.3** 不得滥用举报功能打压其他创作者的资源。
- **5.4.4** 用户期待在 AstroBox 中找到高品质的资源。大量的用户举报、集中的负面评论或售后纠纷，都表明资源可能没有达到这一期待，并会成为我们评估作者是否遵守本准则的依据。
- **5.4.5** 重复或严重的违规行为，会导致你的资源被下架，并可能导致你的创作者账号被封禁。

## 提交之后

通过 CreatorConsole 提交 Pull Request 后，你的资源随即进入审核流程。请谨记以下几点：

- **状态**：你可以在 CreatorConsole 的「资源管理」页面切换到「审核列表」查看审核状态，审核员的意见会直接发布在 Pull Request 中。
- **时间**：审核团队会尽快检查你的资源。模块（需要经过更严格的安全审计）、加密资源与付费资源通常需要更长的时间；因违反同一准则而反复被拒的资源，也需要更长时间才能完成审核。
- **修改**：收到修改意见后，请在原 Pull Request 中完成修改，无需另外提交新的 Pull Request。
- **拒绝与申诉**：如果你对审核结论有疑问，或者希望补充信息，请直接在 Pull Request 中回复审核员。对于「设计不通过」等主观判断，你可以申请扩大审核，我们会进行内部多人投票，并以投票结果决定资源是否通过。
- **问题修复**：对于已上架资源的问题修复版本，除非涉及安全或法律问题，否则我们不会因为资源存在其他问题而推迟发布这次修复。
- **下架**：已上架的资源如果无法再按预期工作、作者不再积极维护，或被发现违反本准则，我们可能会联系作者限期修改，或将资源暂时下架乃至永久下架。

我们期待在 AstroBox 中看到你的作品！

> 本准则将随着审核工作的推进持续更新，资源的实际审核结果请以审核回复为准。已上架的资源，将在下一次提交更新时按照本准则审核。
